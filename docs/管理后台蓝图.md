# 农屿后台管理系统蓝图
### 背景
农屿管理后台作为农屿的后台管理系统，主要包括两大模块：用户信息管理和用户数据分析
### 后台登录部分
管理后台登录不单独实现接口，而是基于已有的用户登录接口，具体逻辑为前端输入学号，无需输入密码，后端查users表判断此学号是否在表中，只要在表中就可以登录，然后根据表的role_code字段值判断用户角色，如果是1则代表用户为普通用户无法进入，响应信息提示“普通用户无法进入管理后台”，如果是2则代表用户为管理员用户可以进入，响应信息提示“农屿管理员用户登录成功”，如果是3则代表超级管理员登录，响应信息提示“农屿超级管理员登录”。如果users表中没有用户所想要登录的学号，那么表示登录失败，提示用户“请您先在农屿app端登录，系统会自动注册您的帐号“
### 用户信息管理模块
用户信息管理模块主要包括全部用户信息的分页展示，用户信息的修改（主要是用户角色的修改，对任何用户的角色修改只有超级管理员才能做，普通管理员只有进入管理后台的权限）
### 用户数据分析模块
用户数据分析模块主要是以可视化图表的方式展示用户行为数据以及农屿用户现状
主要依赖的表结构为
CREATE TABLE IF NOT EXISTS `event_logs` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `event_uuid` CHAR(36) NOT NULL,
  `event_type` VARCHAR(64) NOT NULL,
  `event_time` DATETIME NOT NULL,
  `day_date` DATE NOT NULL,
  `user_id` INT UNSIGNED NOT NULL DEFAULT 0,
  `device_info` VARCHAR(255) NOT NULL DEFAULT '',
  `page_name` VARCHAR(128) NOT NULL DEFAULT '',
  `element_name` VARCHAR(128) NOT NULL DEFAULT '',
  `duration_ms` INT UNSIGNED NOT NULL DEFAULT 0,
  `properties` JSON NOT NULL DEFAULT (JSON_OBJECT()),
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_event_logs_uuid` (`event_uuid`),
  KEY `idx_event_logs_type_time` (`event_type`, `event_time`),
  KEY `idx_event_logs_user_time` (`user_id`, `event_time`),
  KEY `idx_event_logs_day_type` (`day_date`, `event_type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
实际上的事件类型包括”user-enter-app“、”user-ente-page“、”user-click-button“，具体用户进入页面的页面名称参考page_name，用户点击按钮的按钮名称参考element_name
- 用户行为数据（主要是分析哪些功能用得较多，哪些较少）
- 用户数据大屏（主要是展示用户数量、用户活跃量、用户增长趋势等数据）
