# 农屿后台管理系统接口文档集合

本文档汇总了农屿后台管理系统的所有后端接口。

## 1. 管理后台登录

基于已有的用户登录接口逻辑，通过学号进行登录，并验证用户角色权限。

- **接口路径**: `/admin/login`
- **请求方法**: `POST`
- **权限要求**: 无（公开接口）

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| student_no | string | 是 | 学号 |

### 响应结果

- **成功响应 (200 OK)**

```json
{
  "status": "ok",
  "message": "农屿管理员用户登录成功", // 或 "农屿超级管理员登录"
  "data": {
    "user_id": 123,
    "name": "张三",
    "role_code": 2, // 2=管理员, 3=超级管理员
    "token": "123.456.abcdef..."
  }
}
```

- **失败响应**

  - **400 Bad Request**: 未输入学号
    ```json
    { "status": "error", "message": "请输入学号" }
    ```
  - **404 Not Found**: 用户不存在
    ```json
    { "status": "error", "message": "请您先在农屿app端登录，系统会自动注册您的帐号" }
    ```
  - **403 Forbidden**: 普通用户尝试登录
    ```json
    { "status": "error", "message": "普通用户无法进入管理后台" }
    ```

## 2. 用户信息管理

### 2.1 获取用户列表

分页获取所有用户信息，支持通过姓名或学号进行模糊搜索。

- **接口路径**: `/admin/users`
- **请求方法**: `GET`
- **权限要求**: 管理员 (role_code >= 2)

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| page | number | 否 | 页码，默认 1 |
| pageSize | number | 否 | 每页数量，默认 10 |
| keyword | string | 否 | 搜索关键词（匹配姓名或学号） |

### 响应结果

```json
{
  "status": "ok",
  "data": {
    "list": [
      {
        "id": 1,
        "student_no": "202308601",
        "name": "张伟",
        "role_code": 1,
        "status": 1,
        "created_at": "2024-01-01T12:00:00.000Z"
      },
      // ...
    ],
    "total": 100,
    "page": 1,
    "pageSize": 10
  }
}
```

### 2.2 修改用户角色

修改指定用户的角色权限。仅超级管理员可操作。

- **接口路径**: `/admin/users/:id/role`
- **请求方法**: `PUT`
- **权限要求**: 超级管理员 (role_code = 3)

### 请求参数

- **Path 参数**: `id` (用户ID)
- **Body 参数**:

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| role_code | number | 是 | 角色代码 (1=普通用户, 2=管理员, 3=超级管理员) |

### 响应结果

- **成功响应**

```json
{
  "status": "ok",
  "message": "角色修改成功"
}
```

- **失败响应 (403 Forbidden)**

```json
{
  "status": "error",
  "message": "权限不足，需要超级管理员权限"
}
```

## 3. 用户数据分析

### 3.1 功能使用统计

获取用户行为数据中，访问量最高的前10个页面和点击量最高的前10个按钮。

- **接口路径**: `/admin/stats/features`
- **请求方法**: `GET`
- **权限要求**: 管理员 (role_code >= 2)

### 响应结果

```json
{
  "status": "ok",
  "data": {
    "pages": [
      { "name": "首页", "count": 1200 },
      { "name": "个人中心", "count": 800 }
      // ...
    ],
    "elements": [
      { "name": "签到按钮", "count": 500 },
      { "name": "分享按钮", "count": 300 }
      // ...
    ]
  }
}
```

### 3.2 数据大屏概览

获取用户总量、今日日活（DAU）以及近7日的用户增长趋势。

- **接口路径**: `/admin/stats/dashboard`
- **请求方法**: `GET`
- **权限要求**: 管理员 (role_code >= 2)

### 响应结果

```json
{
  "status": "ok",
  "data": {
    "total_users": 5000,
    "dau": 350,
    "growth_trend": [
      { "date": "2024-05-01", "count": 10 },
      { "date": "2024-05-02", "count": 15 },
      // ... (最近7天的新增用户数或总用户数快照，具体视实现而定，当前实现为每日新增注册用户数)
    ]
  }
}
```

获取系统用户的多维度分布数据，包括学院、专业、校区、性别和年级（通过学号解析）。

### 3.4 活跃用户画像

基于用户行为数据和用户属性，分析活跃用户（DAU）的构成。

- **接口路径**: `/admin/stats/active-user-portrait`
- **请求方法**: `GET`
- **权限要求**: 管理员 (role_code >= 2)
- **请求参数**:

## 4. 官方通知发布

### 4.1 发布通知

管理员发布官方通知，支持三种类型：系统更新、系统维护、安全通知。

- **接口路径**: `/admin/notifications`
- **请求方法**: `POST`
- **权限要求**: 管理员 (role_code >= 2)

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| title | string | 是 | 通知标题 |
| content | string | 是 | 通知内容 |
| type | number | 是 | 通知类型：1=系统更新, 2=系统维护, 3=安全通知 |

### 响应结果

```json
{
  "status": "ok",
  "message": "通知发布成功",
  "data": {
    "id": 1
  }
}
```

### 4.2 获取通知列表

分页获取已发布的官方通知列表。

- **接口路径**: `/admin/notifications`
- **请求方法**: `GET`
- **权限要求**: 管理员 (role_code >= 2)

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| page | number | 否 | 页码，默认 1 |
| pageSize | number | 否 | 每页数量，默认 10 |
| type | number | 否 | 按类型筛选：1=系统更新, 2=系统维护, 3=安全通知 |

### 响应结果

```json
{
  "status": "ok",
  "data": {
    "list": [
      {
        "id": 1,
        "title": "系统维护通知",
        "content": "将于今晚进行停机维护...",
        "type": 2,
        "status": 1,
        "created_at": "2024-05-20T10:00:00.000Z",
        "publisher_name": "张三"
      }
    ],
    "total": 50,
    "page": 1,
    "pageSize": 10
  }
}
```

### 4.3 撤回通知

将已发布的通知标记为撤回状态（软删除）。

- **接口路径**: `/admin/notifications/:id`
- **请求方法**: `DELETE`
- **权限要求**: 管理员 (role_code >= 2)

### 响应结果

```json
{
  "status": "ok",
  "message": "通知已撤回"
}
```
